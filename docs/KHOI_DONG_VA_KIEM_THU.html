Khởi động hệ thống và chạy kiểm thử

01Bảng cổng

Bộ cổng này chọn lệch khỏi mặc định (8000 / 3000 / 3001) để không đụng ứng dụng khác đang chạy trên cùng máy.

Đổi cổng backend thì phải đổi kèm NEXT_PUBLIC_BACKEND_URL ở cả hai frontend. Đổi cổng frontend thì phải đổi kèm CORS_ORIGINS trong backend/.env. Sửa một nơi mà quên nơi kia thì triệu chứng là trang mở được nhưng mọi lời gọi đều hỏng, rất mất công lần ra.

02Chuẩn bị

Chỉ làm một lần cho mỗi máy. Máy đã cài rồi thì nhảy thẳng xuống phần Khởi động.

Dùng PowerShell, đừng dùng Git Bash

Git Bash trên máy này không thấy node trong PATH, chạy npm sẽ báo '"node"' is not recognized. Mọi lệnh dưới đây viết cho PowerShell.

Backend — môi trường Python

PowerShell · backend 
PS> cd F:\DoAnTotNghiep\xkld-chatbot\backend
PS> python -m venv venv
PS> .\venv\Scripts\python.exe -m pip install -r requirements.txt

Hai frontend — thư viện Node

PowerShell · frontend + admin 
PS> cd F:\DoAnTotNghiep\xkld-chatbot\frontend
PS> npm ci
PS> cd ..\admin-frontend
PS> npm ci

Tệp cấu hình

Backend cần backend/.env. Thiếu GEMINI_API_KEY hoặc JWT_SECRET thì ứng dụng chết ngay lúc khởi động chứ không chạy tiếp — đó là chủ ý, để lỗi lộ ra ở dòng đầu tiên thay vì ở một câu trả lời sai giữa buổi demo.

Hai frontend không cần tệp cấu hình: chúng tự lấy mặc định http://localhost:8020.

03Khởi động

Năm bước, cần ba cửa sổ terminal mở song song. Đóng cửa sổ nào là tắt phần đó.

  1. MongoDB

    Chạy sẵn dưới dạng dịch vụ Windows, tự bật cùng máy. Kiểm cho chắc:

    PowerShell 
    PS> Get-Service MongoDB

Status   Name      DisplayName
------   ----      -----------
Running  MongoDB   MongoDB Server

    Nếu là Stopped thì chạy Start-Service MongoDB.

  2. Qdrant — kho vector

    Mở Docker Desktop trước, đợi biểu tượng ngừng quay, rồi:

    PowerShell 
    PS> docker start qdrant

    Báo không tìm thấy container (máy mới clone, hoặc đã xoá) thì tạo lần đầu:

    PowerShell · tạo lần đầu 
    PS> docker run -d --name qdrant `
       -p 6333:6333 -p 6334:6334 `
       -v qdrant_storage:/qdrant/storage `
       qdrant/qdrant
    Bỏ qua bước này cũng được

    Backend vẫn lên, website vẫn chạy, đối chiếu hồ sơ vẫn ra kết quả — vì bộ đối chiếu là Python thuần, không gọi mô hình nào. Chỉ khung chat là không trả lời được, do không có kho vector để tra tài liệu.

    Vector nằm trong Docker volume, không nằm trong Git. Máy mới clone repo sẽ có mã nguồn nhưng chưa có collection — phải chạy lại bộ nạp tài liệu.

  3. Backend — terminal 1

    PowerShell · terminal 1 
    PS> cd F:\DoAnTotNghiep\xkld-chatbot\backend
PS> .\venv\Scripts\python.exe -m uvicorn main:app --reload --port 8020

[DB] MongoDB initialized successfully.
INFO:     Uvicorn running on http://127.0.0.1:8020
INFO:     Application startup complete.

    Đợi tới dòng Application startup complete. rồi mới mở terminal sau.

  4. Website khách hàng — terminal 2

    PowerShell · terminal 2 
    PS> cd F:\DoAnTotNghiep\xkld-chatbot\frontend
PS> npm run dev

▲ Next.js — Local: http://localhost:3100

  5. Hệ thống quản trị — terminal 3

    PowerShell · terminal 3 
    PS> cd F:\DoAnTotNghiep\xkld-chatbot\admin-frontend
PS> npm run dev

▲ Next.js — Local: http://localhost:3101

Kiểm thử không cần gì chạy sẵn

Không cần MongoDB, không cần Qdrant, không cần mạng, không tốn hạn mức Gemini. Mọi lời gọi ra ngoài đều được thay bằng bản giả lập. Nhờ vậy chạy được ở bất cứ đâu và cho cùng một kết quả mỗi lần.

Backend

PowerShell · backend 
PS> cd F:\DoAnTotNghiep\xkld-chatbot\backend
PS> .\venv\Scripts\python.exe -m unittest discover -s tests -t .

----------------------------------------------------------------------
Ran 845 tests in 22.578s

OK
-t . là bắt buộc, không phải trang trí

Thiếu nó thì trên máy chưa có .env toàn bộ bộ kiểm thử đổ lỗi nạp module, và thông báo lỗi chẳng gợi ý gì về nguyên nhân thật.

Chạy riêng một nhóm

PowerShell · chạy hẹp 
# Một tệp
PS> .\venv\Scripts\python.exe -m unittest tests.test_matching_engine

# Một lớp
PS> .\venv\Scripts\python.exe -m unittest tests.test_registrations.GuardrailTests

# Một ca duy nhất
PS> .\venv\Scripts\python.exe -m unittest `
       tests.test_registrations.GuardrailTests.test_don_qua_han_giua_luc_doi_chieu_va_luc_dang_ky

# In tên từng ca trong lúc chạy
PS> .\venv\Scripts\python.exe -m unittest discover -s tests -t . -v

Ba bộ nghiệm thu chạy tay — có gọi mô hình thật

Ba bộ dưới đây gọi mô hình thật và cần mạng, nên cố ý không nằm trong unittest: bộ kiểm thử thường phải chạy được khi mất mạng và khi hết hạn mức. Chạy tay trước mỗi mốc bàn giao.

LệnhĐo cái gì
python -m scripts.nghiem_thu_doc_cv Bộ đọc CV trên tám hồ sơ mẫu. Bốn cột ĐÚNG / SAI / THIẾU / NGOÀI PHẠM VI — cột SAI là cột duy nhất đáng lo.
python -m scripts.nghiem_thu_tu_van Bot tư vấn trên 11 ca cố định, mỗi ca khóa lại một lỗi đã xảy ra thật, có ghi ngày đo.
python -m scripts.nghiem_thu_chatbot Khung chat hỏi đáp trên bộ câu hỏi mẫu.
Hạn mức 20 lượt gọi mỗi ngày cho mỗi model, tính theo dự án Google

Không đủ cho cả ba bộ trong một lượt, nên cả ba đều bồi kết quả dần qua nhiều đợt và ghi kèm tên model đã đo từng dòng. Chạy lại lệnh cũ là nó đo tiếp phần còn nợ.

Quan trọng hơn: lượt nào không gọi được mô hình thì không được ghi kết quả. Đo ngày 28/09, khi chưa có chốt này: hạn mức cạn sau câu đầu tiên, mười câu sau nhận câu ghép sẵn, và ba ca chuyển sang ĐẠT vì "không biết" tình cờ thỏa điều kiện của chúng. Một bộ đo tự khen mình khi hệ thống chết thì tệ hơn là không có bộ đo nào.

06Dừng

Bấm Ctrl+C trong từng terminal. Qdrant thì docker stop qdrant. MongoDB cứ để chạy, nó là dịch vụ nền và không tốn gì.

07Sự cố hay gặp

Cổng đã bận

Backend báo [Errno 10048] error while attempting to bind on address ('127.0.0.1', 8020) nghĩa là tiến trình cũ chưa chết hẳn. Tìm và tắt:

PowerShell · giải phóng cổng 
PS> Get-NetTCPConnection -State Listen -LocalPort 8020 |
       ForEach-Object { Stop-Process -Id $_.OwningProcess -Force }
Đừng chạy npm run build khi npm run dev đang chạy

Hai lệnh cùng ghi vào thư mục .next. Triệu chứng là trang mở ra mất sạch giao diện, trông như hỏng CSS — rất dễ đi tìm nhầm chỗ. Lỡ dính thì Ctrl+C, xoá .next, chạy lại:

PowerShell · dọn .next 
PS> Remove-Item -Recurse -Force .next
PS> npm run dev

Trang kêu “phiên tư vấn đã hết hạn”, tải lại bao nhiêu lần cũng vậy

Mã phiên lưu trong trình duyệt đã lệch khỏi cookie — hay xảy ra khi backend khởi động lại với JWT_SECRET khác. Mở Console của trình duyệt (F12) và gọi:

DevTools Console 
> localStorage.removeItem("xkld-candidate-session"); location.reload()

Đăng nhập quản trị báo sai mật khẩu dù gõ đúng

Chuỗi băm mật khẩu có dạng pbkdf2_sha256$600000$muoi$bam. Ba dấu $ đó bị Docker Compose nuốt mất khi nội suy biến môi trường, nên tài khoản quản trị đầu tiên được tạo với chuỗi băm hỏng. Triệu chứng duy nhất là “sai mật khẩu” với mật khẩu đúng. Cách chạy tay trong tài liệu này không dính lỗi ấy; nếu chạy bằng Docker thì env_file phải khai format: raw.

Chatbot trả lời nhưng không dẫn được nguồn

Qdrant chưa chạy, hoặc chạy rồi nhưng collection còn rỗng. Kiểm bằng python -m scripts.check_qdrant trước khi nghi ngờ phần trả lời.
